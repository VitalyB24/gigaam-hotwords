# gigaam-hotwords

*[English version](README.md)*

Распознавание русской речи на обычном процессоре с [GigaAM v3](https://github.com/salute-developers/GigaAM) и
необязательным словарём терминов. Один скрипт, `g2h.py` (GigaAM с подсказкой терминов, hotwords): на входе длинная
запись (встреча на два-три часа), на выходе за несколько минут — транскрипт с таймкодами и субтитры. Словарь
подталкивает декодер к написанию аббревиатур и названий, принятому в ваших документах («ТТН», «ТН ВЭД»), но не даёт
акустической модели придумывать слова, которых не было.

## Зачем

Whisper large-v3 хорошо распознаёт русские деловые встречи, но на процессоре медленно даже в пакетном режиме (около
0,4 длительности записи) и время от времени пропускает целую фразу внутри 25-секундного куска. GigaAM v3 — русская
модель, её CTC-вариант справляется с двухчасовой записью за пару минут. На двух длинных встречах (2 ч 23 мин и
2 ч 47 мин) против пакетного Whisper large-v3 на тех же кусках:

- слов на 10 % больше, ни одного 30-секундного окна, где потеряна бо́льшая часть речи (у Whisper — 14), и намного меньше
  пропавших фраз, которые подтверждает третья, независимая расшифровка (95 слов против 589);
- около 3 минут на запись при 16 потоках вместо примерно часа.

Но обычный GigaAM пишет аббревиатуры проекта на слух. CTC-модель выдаёт вероятность каждого токена на каждом кадре,
поэтому декодеру можно подсказать, как выглядят слова предметной области: режим со словарём добавляет небольшую
надбавку путям, которые пишут известный термин, а решает по-прежнему звук.

## Как устроено

1. **Нарезка.** Детектор речи faster-whisper (Silero VAD, пауза 500 мс) режет запись на куски речи не длиннее 25 с и
   склеивает их ровно так, как это делает пакетный режим faster-whisper. Пакетная транскрипция faster-whisper того же
   файла даёт те же куски, если запущена с теми же настройками VAD и `chunk_length=25` (её собственное умолчание —
   30 с); тогда два транскрипта можно сравнивать кусок к куску. Детектор работает в основном Python (том, где стоит
   faster-whisper); `g2h.py` вызывает его подпроцессом, и окружение GigaAM остаётся компактным.
2. **Акустика.** Каждый кусок проходит энкодер GigaAM `v3_e2e_ctc` на процессоре (по умолчанию 16 потоков).
3. **Декодирование.**
   - Без словаря — жадное CTC-декодирование, в точности как у самого GigaAM.
   - Со словарём — поиск лучом по префиксам CTC. Оценка гипотезы — её лучшее выравнивание (максимум по выравниваниям,
     а не их сумма), ширина луча 16; на каждом кадре пробуются пустой символ и токены, чей логарифм вероятности не
     ниже лучшего на кадре минус 10. Каждый термин разбивается на токены SentencePiece (до пяти разбиений на форму;
     у термина есть ещё формы со строчной и с заглавной первой буквой, если он не набран прописными и его первое
     слово не аббревиатура, как в «ТТН на возврат»). Гипотеза получает `w` за каждый
     токен термина, который она пишет от начала слова; сошла с термина, не дописав, — надбавка снимается, дописала —
     остаётся, после термина допускается окончание до трёх букв («НДС» → «НДСы»).
   - При `w = 0` поиск лучом возвращает жадный результат при любой ширине луча — это проверяют тесты.

## Что нужно

- Процессор; Windows или Linux. Около 2,5 ГБ памяти на запись 2,5 ч.
- Python 3.12 или новее (разработка — на 3.13) в двух ролях:
  - виртуальное окружение для GigaAM: `torch` и `torchaudio` 2.10 для процессора (`constraints.txt` закрепляет
    версии, на которых инструмент проверен), GigaAM из его репозитория (проверен на коммите `7447938`),
    `sentencepiece`, `numpy`;
  - основной Python с `faster-whisper` (проверен с 1.2.1) — для нарезки.
- `ffmpeg`, чтобы достать звук из видео.

Веса GigaAM (`v3_e2e_ctc`, около 450 МБ вместе с токенизатором) пакет `gigaam` скачивает при первом запуске в
`models/` рядом со скриптом — с собственного сервера раздачи GigaAM; контрольную сумму пакет проверяет сам.

## Установка

```bash
git clone https://github.com/salute-developers/GigaAM
python -m venv venv
venv/Scripts/python -m pip install -c constraints.txt torch torchaudio --index-url https://download.pytorch.org/whl/cpu
venv/Scripts/python -m pip install -c constraints.txt -e ./GigaAM
python -m pip install faster-whisper
```

На Linux интерпретатор окружения — `venv/bin/python`. Основной Python находится сам — тот, из которого создано
виртуальное окружение; другой можно указать через `--vad-python`.

`pyproject.toml` перечисляет те же пакеты (`dependencies`, версии torch — как в `constraints.txt`), чтобы их видели граф
зависимостей GitHub и алерты безопасности. Ставить окружение через него не нужно: `pip install .` взял бы torch с PyPI,
а не из CPU-индекса PyTorch.

## Запуск

```bash
ffmpeg -i meeting.webm -ac 1 -ar 16000 -vn -acodec pcm_s16le meeting.wav
venv/Scripts/python g2h.py --audio meeting.wav --out meeting.txt --dict terms.txt
```

| Параметр | Что делает |
|---|---|
| `--audio`, `--out` | WAV (16 кГц, моно, 16 бит) и транскрипт, который записать |
| `--srt` | куда записать субтитры (по умолчанию — рядом с `--out`) |
| `--title` | первая строка шапки транскрипта |
| `--dict`, `--w` | словарь терминов и надбавка за токен термина (по умолчанию 3); без `--dict` — обычный GigaAM |
| `--reserve K` | места луча для гипотез, лучших по одной акустике, без надбавок словаря (по умолчанию 4; 0 — выключить); см. «Словарь» |
| `--words JSON` | записать ещё и время и уверенность слов: `{"chunks": [{"start", "end", "conf", "words": [[слово, начало, конец, уверенность], …]}]}` |
| `--threads` | потоки процессора для torch (по умолчанию 16) |
| `--keep-logprobs NPZ` | сохранить ещё и выход CTC по каждому куску (около 200 МБ на 2,5 ч) |
| `--from-logprobs NPZ` | перекодировать сохранённый выход CTC вместо `--audio`: без модели, около 20 с на 2,5 ч |
| `--dict-check` | показать, как каждый термин раскладывается на токены (и отказы), и выйти (код 2, если у формы нет годного разбиения) |
| `--limit-sec N` | только первые N секунд — быстрая проба установки |
| `--log FILE` | дописывать журнал ещё и в файл |
| `--models`, `--vad-python` | каталог весов и Python с faster-whisper, если не по умолчанию |

**Выход.** Две строки шапки с `#`, затем по строке на кусок: `[H:MM:SS → H:MM:SS] текст`. Субтитры — в `.srt`
рядом. По ходу работы каждый кусок дописывается в файл `.partial.txt` с именем `--out` без расширения
(`rec.txt` → `rec.partial.txt`), так что убитый прогон оставляет готовый текст; в конце этот файл удаляется.
В журнале — метки `=== START g2h`, `=== DONE g2h` и `=== FAILED g2h`; строка с `!` — предупреждение (форма словаря,
которая никогда не получит надбавку; файл журнала или partial, который не удалось записать или удалить), прогон при
этом продолжается. Код выхода 0 — успех, 1 — нечего распознавать (нет файла, он пуст, в нём нет речи), 2 — сбой;
неверный аргумент и несуществующая папка для результата дают отказ до начала работы. На Windows скрипт не даёт
машине уснуть, пока работает.

**Скорость.** Запись 2 ч 23 мин при 16 потоках: нарезка 10 с, энкодер 2 мин, поиск лучом со словарём из 36 терминов
20 с.

## Словарь

Текстовый файл в UTF-8, один термин на строку, в том написании, в каком он должен попасть в транскрипт; аббревиатуры —
прописными; `#` начинает комментарий (пример — `terms.example.txt`). То, что прячет редактор, — метка порядка байтов,
символы нулевой ширины, неразрывные и двойные пробелы — при чтении вычищается, повтор термина считается один раз.
Кладите только термины, которые действительно звучат и которые обычное декодирование пишет неверно: каждый термин —
путь, на который декодер приглашают свернуть.

`w` — размен терминов на речь. Небольшая надбавка чинит термин, в котором модель не уверена; большая позволяет
гипотезе, написавшей начало термина, вытеснить из луча продолжение настоящей речи: если термин так и не дописан,
слова после него теряются. Проверьте словарь, прежде чем на него полагаться:

1. распознайте запись один раз с `--keep-logprobs rec.npz`;
2. перекодируйте с каждым вариантом словаря или `w`: `--from-logprobs rec.npz --dict terms.txt --w 1` (секунды на
   вариант) — и один раз без `--dict`;
3. сравните: версия со словарём должна сохранить не меньше 99 % слов обычной, и термины не должны появляться там, где
   их не говорили (типичный признак — несколько терминов словаря подряд).

`--reserve K` убирает эту потерю: K мест луча отдаются гипотезам, лучшим по одной акустике, без каких-либо надбавок
словаря, поэтому продолжение речи остаётся в луче, а термин, который так и не дописан, проигрывает ему в конце куска.
У резерва есть предел: после того как словарь исправил термин в куске, резерв стережёт линии без этого исправления,
и простое продолжение исправленной линии всё ещё может быть вытеснено из луча.
На трёх записанных встречах (от 1 ч 50 мин до 2 ч 47 мин, словарь из 36 терминов) со сверкой по независимому
транскрипту Whisper: `w = 2` без резерва потерял 9 фраз (112 слов); с `--reserve 4` ни одна фраза не потеряна ни при
`w = 2`, ни при `w = 3`, а `w = 3 --reserve 4` исправил написание терминов 39 раз против 28 при `w = 1` без резерва и
ухудшил подтверждённо 1 раз против 2. Полные прогоны тех же трёх записей (звук → куски → энкодер → декодер) совпали с
перекодированием слово в слово, поэтому `w = 3 --reserve 4` — умолчание; `--w 1 --reserve 0` воспроизводит прежнее.
Настройка проверена на одном словаре из 36 терминов: свой словарь проверьте (три шага выше и `--dict-check`), прежде
чем на него полагаться.

`--dict-check` показывает, есть ли у каждой формы каждого термина годное разбиение на токены; форма без него
надбавку не получает никогда. Код выхода — 2, если такая форма есть, иначе 0; обычный прогон называет такие формы в
журнале и продолжает работу.

Термин не получает надбавку, если начинается сразу после первых слов более длинного термина словаря, пока тот ещё
сопоставляется: при термине «ставка НДС» в словаре «НДФЛ» во фразе «ставка НДФЛ» распознаётся как без словаря.

## Время слов и уверенность

`--words rec.words.json` выравнивает распознанные токены обратно по кадрам CTC (лучший путь) и пишет по каждому куску
его слова со временем начала и конца в записи и уверенностью — средним геометрическим лучших вероятностей токенов на
их кадрах, — а также уверенность самого куска. Кусок — склеенные участки речи, поэтому время пересчитывается через эти
участки; файлы, сохранённые с `--keep-logprobs`, несут их с собой, и перекодирование сохраняет точное время. Рядом с
`chunks` файл называет `audio`, `model` и `decoder`; перекодирование добавляет `approximate_times` — `true`, если в
сохранённом файле нет участков речи и время распределено по куску линейно. У куска без текста `"conf": null`. Низкая
уверенность куска отмечает места, куда стоит посмотреть второй раз: на одной встрече 6 из 10 мест, где независимый
транскрипт расслышал речь, которой нет в прогоне со словарём, пришлись на 6 % самых неуверенных кусков.

## Разработка

Перед каждым коммитом — проверки; CI запускает те же на каждый push:

```bash
ruff check .
pytest
```

Тесты работают на синтетике — заменитель токенизатора и вручную собранные логарифмы вероятностей, — поэтому ни модель,
ни `torch` им не нужны; что им нужно — в `requirements-dev.txt`. Репозиторий англоязычный (эта страница — перевод);
концы строк в git — LF (`.gitattributes`).
